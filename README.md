# 시각장애인 실내 대피 AI 내비게이션 (MVP)

> 재난 때 '가까운 출구'를 알려주는 것이 아니라, 시각장애인이 **현재 위치에서 연기·혼잡·장애물을 피해
> 실제로 이동할 수 있는 경로**를 음성·진동으로 안내한다.

4주 MVP 범위: **한 건물 한 층(병원 3층)의 모의대피 실험**.
"완전 자율 대피"가 아니라 **접근 가능한 동적 경로 + 안내 UX 검증**이 목표다.

---

## 아키텍처

```
┌──────────────────────────┐        ┌────────────────────────────┐       ┌───────────┐
│ frontend/ (PWA, 순수 JS) │  REST  │ backend/ (Node + Express)   │ Admin │ Firestore │
│  · 사용자 앱 (음성·진동) │ -----> │  · 경로 계산 (권위)         │  SDK  │  hazards  │
│  · 관제 대시보드         │        │  · 위험 상태 검증·인증      │ ----> │  sos      │
│                          │ <----- │  · 화재수신기/BMS 웹훅      │       │  positions│
│  오프라인 폴백 계산      │  SSE   │  · SSE 브로드캐스트         │       │  metrics  │
└──────────────────────────┘        └────────────────────────────┘       └───────────┘
                    └──────── shared/ (지도 그래프 + Dijkstra) ────────┘
```

**프론트엔드는 Firestore에 직접 접근하지 않는다.** 모든 DB 접근은 백엔드가 서비스 계정으로 수행한다.
그래서 브라우저에 Firebase 자격증명이 노출되지 않고, 위험 상태(hazards) 쓰기를 관제 인증으로만
통제할 수 있다 — 잘못된 위험 정보 주입은 곧바로 오안내 → 인명위험이기 때문이다.

`shared/`는 지도 그래프와 경로탐색 알고리즘의 **단일 진실 소스**다. 백엔드가 권위 있는 계산을 하지만,
통신이 끊겼을 때 프론트가 캐시된 위험 상태로 직접 계산해 안내를 이어가야 하므로
(`npm run sync`가 `frontend/shared/`로 복사) 양쪽이 같은 코드를 쓴다.

## 개발 실행

```bash
npm install       # 루트 + backend 의존성 (npm workspaces)
npm run dev       # 백엔드 + 프론트엔드를 함께 띄우고 계속 살려 둔다
```

한 명령으로 두 서버가 뜨고, **둘 중 하나가 죽으면 2초 뒤 자동으로 다시 뜬다.**
이미 떠 있는 프로세스가 있으면 새로 띄우지 않고 그대로 쓰므로,
**VS Code `F5`로 백엔드를 디버깅 중이어도 충돌하지 않는다** (실행 구성: `백엔드 실행·디버그`).

- **시연 콘솔** → http://localhost:5173/demo.html ← **발표는 이 화면 하나면 됩니다**
- 사용자 앱 → http://localhost:5173/index.html
- 관제 대시보드 → http://localhost:5173/admin.html
- 보호자 화면 → http://localhost:5173/guardian.html (코드 입력)
- 도면 편집기 → http://localhost:5173/architect.html

### 시연 콘솔 — 한 화면에서 모두 조작

`demo.html` 하나로 대피와 화재를 전부 조작한다. 화면을 오갈 필요가 없다.

```
┌─────────────────────┬──────────────────────┐
│                     │  ① 어디서 출발하나요? │
│   지도               │  ② [ 대피 시작 ]      │
│   (클릭 = 불 지르기)  │  ③ 불 크기 [===|--]   │
│                     │                      │
│                     │  지금 안내            │
│                     │  "정면으로 15걸음…"    │
│                     │  [자동으로 걷기][한 걸음]│
└─────────────────────┴──────────────────────┘
```

1. **출발지**를 고르면 저장된 장소 설명을 읽어준다
2. **대피 시작** → 음성 안내가 오른쪽에 그대로 표시된다
3. **지도를 클릭**하면 그 자리에 불이 나고, 경로가 다시 잡힌다

상단 **건물** 선택으로 도면을 바꿀 수 있고, **처음부터**로 화재·연기·온도를 한 번에 되돌린다.
연기·혼잡·온도 센서처럼 세부 조작이 필요하면 아래 *자세한 화면 열기*에서 관제 대시보드로 간다.



프론트 개발 서버가 `/api/*`를 백엔드(:8080)로 프록시하므로 **같은 출처**가 되어
CORS 설정 없이 SSE까지 그대로 흐른다 (배포 구성과 동작이 동일하다).
`/shared/*`는 사본이 아니라 `shared/` 원본을 직접 읽는다.

**파일을 고치면 브라우저가 알아서 반영한다** — 새로고침(Ctrl+Shift+R)이 필요 없다.
`frontend/`와 `shared/`를 감시하다가 변경이 생기면 열려 있는 모든 탭에 알린다.

| 고친 파일 | 브라우저 동작 |
|---|---|
| `.css` | **새로고침 없이** 스타일만 교체 — 대피 안내 중이던 화면 상태가 유지된다 |
| `.js` · `.html` · `shared/*` | 페이지 다시 읽기 |
| 개발 서버 자체 | 재시작을 감지해 다시 읽기 |

리로드 스크립트는 개발 서버가 HTML을 내보낼 때 주입하므로 **배포본에는 들어가지 않는다**.

백엔드를 아직 안 띄웠다면 프록시가 503을 돌려주고, 프론트는 **오프라인 폴백**으로 전환해
캐시된 지도로 안내를 계속한다 — 이 동작 자체를 확인하는 용도로도 쓸 수 있다.

| 실행 방식 | 명령 | 용도 |
|---|---|---|
| **둘 다** | `npm run dev` | 백엔드+프론트, 죽으면 자동 재시작 |
| 프론트만 | `npm run dev:frontend` | :5173, `/api`는 :8080으로 프록시 |
| 백엔드만 | **VS Code F5** | :8080, 중단점 디버깅 |
| 백엔드만 (터미널) | `npm run dev:backend` | 파일 변경 시 자동 재시작 |
| 통합 1포트 | `npm start` | :8080 하나로 프론트까지 서빙 (배포 확인용) |

### 연결이 끊기지 않게 한 것들

시연 도중 서버가 내려가면 대피 안내를 받던 화면과 보호자 화면이 동시에 끊긴다. 그래서:

- **프로세스 감시** — 어느 쪽이 죽어도 2초 뒤 다시 띄운다 (`scripts/start-all.mjs`).
  같은 오류로 연달아 즉시 죽으면 크래시 루프를 멈추고 원인을 알린다.
- **SSE 자동 재연결** — EventSource는 서버가 200이 아닌 응답을 주면(백엔드가 죽었을 때
  프록시가 내리는 503이 그렇다) **재연결하지 않고 영구히 닫힌다**. 그러면 백엔드가 살아나도
  화면은 계속 "연결 끊김"에 머문다. 닫힘을 직접 감지해 1→2→…→10초 백오프로 다시 연다.
- **프록시 소켓 재사용 금지** — 백엔드가 재시작되면 풀에 남은 죽은 소켓 때문에
  복구 직후 첫 요청이 실패한다. 개발 프록시에서는 매번 새로 연결한다.
- **예외로 죽지 않는 백엔드** — 요청 하나의 오류가 프로세스를 내리지 않도록 로그만 남긴다.
- **끊긴 동안에도 안내는 계속** — 프론트가 캐시된 도면·위험 상태로 직접 경로를 계산한다.

실제로 백엔드를 강제 종료해 확인한 결과: 프론트가 **3초 만에 스스로 재연결**하고
복구 직후의 실시간 이벤트도 정상 수신했다. 프론트를 죽였을 때는 **2초 만에 자동 복구**됐다.

포트가 이미 쓰이고 있어도 개발 서버는 죽지 않는다. **이전 실행이 남아 있으면** 그 사실을 알리고
기존 서버를 쓰라고 안내하며, **다른 프로그램이 점유했으면** 다음 포트로 옮겨 뜬다.
포트를 직접 비우려면 `npx kill-port 5173` (macOS/Linux는 `lsof -ti:5173 | xargs kill`),
다른 포트를 쓰려면 `FRONTEND_PORT=3000 npm run dev`.

Firebase 설정이 없으면 백엔드가 **인메모리 저장소**로 뜬다. 실시간 전파(SSE)·경로 재탐색·구조요청까지
전부 동작하므로 시연에는 충분하다. 여러 기기를 같은 Wi-Fi에서 붙이면 서로 실시간 연동된다.

시연 순서: 사용자 앱에서 **301호 진료실 앞** 선택 → **대피 시작** → 데모 패널의 **자동 이동** →
관제에서 통로 클릭으로 화재 발생 → 사용자 앱이 즉시 재탐색 안내.

## Firebase 연동

1. [Firebase 콘솔](https://console.firebase.google.com)에서 프로젝트 생성 후 **Firestore Database** 활성화
2. 프로젝트 설정 → 서비스 계정 → **새 비공개 키 생성** → `backend/serviceAccountKey.json`으로 저장
3. `backend/.env.example` → `backend/.env` 복사 후 값 입력

```bash
FIREBASE_PROJECT_ID=your-project-id
GOOGLE_APPLICATION_CREDENTIALS=./serviceAccountKey.json
ADMIN_TOKEN=아무_긴_문자열     # 설정하면 관제 API에 x-admin-token 헤더 필요
```

4. `npm run dev` → 로그에 `[repo] Firestore 연결됨` 확인
5. 보안 규칙 배포: `firebase deploy --only firestore:rules`
   (`firestore.rules`는 **클라이언트 직접 접근을 전부 차단**한다. Admin SDK는 규칙을 우회하므로 백엔드는 정상 동작)

배포는 프론트 → Firebase Hosting, 백엔드 → Cloud Run 조합을 가정했다 (`firebase.json`의 `/api/**` rewrite).

## API

| DELETE | `/api/plans/:id` | 도면 삭제 (사용 중이면 409, 인증 필요) |
| GET/PUT | `/api/plans/:id/image` | 도면 이미지 (data URI) |
| POST | `/api/fires` | **임의 좌표에 화재 발생** → 반경 안 통로 자동 차단 |

| GET | `/api/hazards/manual` | 관제가 직접 지정한 위험만 (감사용) |
| PUT | `/api/hazards/:edgeId` | `{type}` 위험 설정 (인증 필요) |
| DELETE | `/api/hazards/:edgeId` | 위험 해제 (인증 필요) |
| POST | `/api/hazards/reset` | 시나리오 초기화 (인증 필요) |
| POST | `/api/sensors/fire-panel` | 화재수신기·BMS 웹훅 (건물 연동 자리) |
| GET/POST | `/api/sos` | 구조요청 조회·전송 (보호자 연락처 자동 첨부) |
| GET/PUT | `/api/positions[/:userId]` | 대피자 위치 (상태 전이 시 보호자 알림 생성) |
| GET/POST | `/api/metrics` | 재탐색 시간 KPI |
| POST | `/api/guardians` | 보호자 등록 → 공유 코드 발급 |
| GET | `/api/guardians/:userId` | 등록된 보호자 조회 |
| GET | `/api/guardian/:code` | 보호자 화면 진입 (대상자 현재 상태) |
| GET | `/api/alerts` | 보호자 알림 이력 |
| GET | `/api/stream` | **SSE** — 변경 실시간 push (`?code=`로 보호자 스코프) |

인증 필요 = `ADMIN_TOKEN` 설정 시 `x-admin-token` 헤더 필요

## 데모 시나리오 (발표용)

**http://localhost:5173/demo.html 한 화면에서 아래를 전부 보여줄 수 있다.**

병원 3층, 301호 진료실 앞에서 화재경보. 초기 상태: **계단 A(동쪽)는 연기 감지, 엘리베이터는 화재 시 자동 제외**.

| 단계 | 조작 | 기대 동작 |
|---|---|---|
| 1 | 대피 시작 | 긴 진동 1회 + "대피 모드를 시작합니다" → 최단 접근가능 출구(남쪽 비상구)로 안내 |
| 2 | 관제에서 남쪽 램프(E11)에 화재 | 2초 이내 재탐색 → 계단 B(서쪽)로 우회, 회전 시 짧은 진동 |
| 3 | 계단 B 통로(E9)도 차단 | 남은 출구(계단 A)는 연기 → **접근 가능 경로 없음** → 안전상태 전환, 구조요청 자동 전송 |
| 4 | 데모 패널 "경로 이탈 재현" ×2 | 확신도 하락 → 기준(40%) 미달 시 임의 안내 중단 + 구조요청 |
| 5 | 백엔드 종료 후 걷기 | 배지가 "오프라인"으로 바뀌고 캐시된 지도·위험 상태로 안내 계속 |
| 6 | 사전에 보호자 등록 후 대피 시작 | 보호자 화면에 긴급 배너·브라우저 알림 + 위치·경로·현재 안내가 실시간 표시 |
| 7 | 관제에서 화재 발생 도구로 **지도 아무 곳이나 클릭** | 그 지점 반경의 통로가 막히고 사용자가 즉시 우회 안내를 받음 |
| 7-1 | 화재 목록에서 **＋ 확산** 반복 | 불이 번져 갈 곳이 없어지면 안전상태 + 구조요청 |
| 8 | 관제에서 온도 도구로 통로에 71°C 주입 | 임계값(60°C) 초과 → 그 구간을 빼고 재탐색, 지도에 온도 배지 표시 |
| 8-1 | 교차점(원)에 82°C 주입 | 연결된 모든 통로 차단 → 갈 곳이 없으면 안전상태 + 구조요청 |
| 9 | 도면 편집기에서 다른 건물 도면 올리고 장소 설명 저장 후 활성화 | 열려 있는 모든 화면이 새 도면으로 전환, 그 도면 기준으로 안내 |
| 10 | 사용자 앱에서 **여기가 어디인가요?** | 저장해 둔 장소 설명·촉각 단서를 음성으로 읽어줌 |
| 11 | **방향 찾기** 켜고 폰을 좌우로 훑기 | 맞는 방향에서 진동이 끊기지 않음 — 각도 없이 몸으로 찾음 |

검증 가설 매핑: ① 진동+음성 병행 이해율(6개 명령 규칙) ② 불확실성 감지(확신도·안전상태)
③ 재탐색 2초 이내(관제 KPI 패널에 ms 기록) ④ 관제·유지관리 가치(대시보드·센서 웹훅).

## 도면 주입 — 건물 설계도로 대피 경로 만들기

지도는 코드에 하드코딩되어 있지 않다. **건물 도면을 넣으면 그 도면 기준으로 안내한다.**

도면 편집기 → http://localhost:5173/architect.html

| 단계 | 하는 일 |
|---|---|
| 1 | 도면 이미지(PNG/JPG) 업로드 — 브라우저에서 자동 축소·압축 (900KB 이하) |
| 2 | **이 층의 실제 가로 폭(m)** 입력 → 축척(`metersPerUnit`) 자동 계산 |
| 3 | 도면을 클릭해 **장소** 찍기 (실·교차점·출구·엘리베이터) |
| 4 | 각 장소에 **이름·설명·촉각 단서** 저장 ↓ |
| 5 | 두 장소를 이어 통로 만들기, 따라갈 벽(좌/우) 지정 |
| 6 | 저장 → **이 도면으로 안내 시작**(활성화) |

### 대피도 인식 — 3~5단계를 모델이 대신하기

한 층에 장소 20~30곳을 손으로 찍고 잇는 일이 도면 등록의 대부분이다.
`ml/`에 그 첫 단계를 대신하는 탐지 모델과 학습 데이터가 있다.

층별 피난안내도 사진에서 **비상구·계단·엘리베이터·소화기·소화전·현재위치·문·실**을 찾고,
실 사각형 바깥을 복도로 삼아 지점들을 이어 도면 JSON을 만든다.
그 JSON을 편집기의 **가져오기**로 열면 3~5단계가 채워진 채로 시작한다.

학습은 두 단계다. **1부**는 합성 도면 100장(`ml/dataset/`에 들어 있음)으로 기호 생김새를
크게 잡고, **2부**는 실제로 안내할 건물의 피난안내도 100장을 찍어 이어서 학습한다.
1부만으로는 실제 사진에서 성능이 떨어진다 — 1부는 2부의 라벨링 시간을 17시간에서
3시간으로 줄이기 위한 발판이다(1부 모델이 밑라벨을 깔아 준다).

- 학습: `ml/train_colab.ipynb` (코랩, 1부 20~30분 + 2부 15분)
- 실제 도면 수집: `ml/label_assist.py`(밑라벨) → labelImg 검수 → `ml/import_real.py`(병합)
- 자세한 내용은 [ml/README.md](ml/README.md)

**모델이 만든 것은 초안이다.** 편집기에서 사람이 확인하고 고친 뒤 활성화한다 —
잘못된 도면은 그대로 오안내가 된다.

### 샘플 3D 도면 — 가천관 3층

서버가 뜰 때 `가천관 3층` 도면이 자동 등록된다 (`shared/plans/gachon-3f.svg` + `shared/gachon-plan.js`).
벽에 두께와 그림자를 넣어 입체로 보이게 하되 **바닥은 정사영을 유지**했다 —
아이소메트릭으로 기울이면 방향에 따라 거리가 최대 1.7배까지 왜곡되어 "몇 걸음"을 계산할 수 없기 때문이다.

저장된 장소 5곳 (모두 설명·촉각 단서 포함):

| 장소 | 유형 | 촉각·소리 단서 |
|---|---|---|
| 312호 강의실 앞 | 실 | 오른쪽 벽에 손잡이, 발밑에 점자블록 시작 |
| 중앙 로비 | 교차점 | 천장이 높아 발소리가 울림, 오른쪽에서 라운지 소리 |
| 북측 복도 교차점 | 교차점 | 점자블록이 십자로 바뀜, 정면에 사무실 문 |
| 동편 비상계단 | **출구** | 문 앞 경고 점자블록, 손잡이 오른쪽 |
| 서편 비상계단 | **출구** | 아래에서 찬 공기, 난간 왼쪽 |

312호에서 출발하면 **서편 계단**(32.7m)이 최단이고, 서편 통로가 과열되면 **동편 계단**으로 재탐색한다.

### 장소 저장 — 위치를 말로 설명하기

도면 위 각 장소에 **설명**과 **촉각·소리 단서**를 적어 두면, 사용자가 앱에서
**여기가 어디인가요?** 를 눌렀을 때 그대로 읽어준다.

```
"여기는 중앙 복도 교차점입니다.
    복도가 좌우로 갈라지는 곳입니다.
    바닥의 점자블록이 십자 모양으로 바뀝니다.
    다음 지점까지 9걸음 남았습니다."
```

이 설명을 **이동 안내에 자동으로 끼워 넣지 않고 버튼으로 뺀 이유**가 있다.
대피 중 음성은 짧고 오해 없어야 한다는 게 이 프로젝트의 안내 규칙인데,
매 지점마다 설명을 읽으면 정작 중요한 "직진·회전" 명령이 묻힌다.
방향을 잃었다고 느낄 때만 사용자가 직접 눌러 확인하게 했다.

설명은 대피 전 **시작 위치를 고를 때**와 **QR을 찍었을 때**도 들려준다(그때는 시간 여유가 있다).
보호자 화면에도 대상자의 현재 장소 설명이 함께 표시된다.

음성으로 읽히므로 **200자를 넘으면 저장이 거부**된다.
편집기 오른쪽 **저장된 장소** 목록에서 설명이 적힌 곳과 아직 안 적은 곳을 한눈에 볼 수 있다.

축척이 곧 "몇 걸음"이 되므로 2단계가 안내 정확도를 좌우한다.
저장 시 도면을 검증한다 — 출구가 없거나, 없는 지점을 잇는 통로가 있거나, id가 중복되면 **거부**한다.
출구까지 이어지지 않는 고립된 지점은 경고로 알려준다(편집 중일 수 있으므로 저장은 허용).

다른 도구에서 만든 도면은 **JSON 가져오기**로 넣을 수 있다(`POST /api/plans`와 같은 형식).
도면을 활성화하면 열려 있는 모든 사용자 앱·관제·보호자 화면이 SSE로 즉시 새 도면을 받는다.

```jsonc
{
  "id": "office-5f", "name": "사무동 5층",
  "metersPerUnit": 0.04,          // 도면 1px = 4cm
  "stepLength": 0.7,
  "image": { "width": 1400, "height": 900 },
  "nodes": [
    { "id": "R1", "name": "501호 회의실 앞", "x": 300, "y": 700, "type": "room",
      "description": "회의실 문을 등지고 서면 복도가 정면으로 이어집니다.",  // 저장된 장소 설명
      "landmark": "오른쪽 벽에 소화기가 있습니다." }                          // 촉각·소리 단서
  ],
  "edges": [ { "id": "C1", "a": "R1", "b": "H1", "wall": "right" } ]
}
```

노드 유형: `room` `junction` `exit` `elevator` `stair` — **`exit`가 대피 목표**가 되고,
`elevator: true` 통로는 화재 모드에서 자동 제외된다.

## 임의 지점 화재 → 회피 경로

**관제에서 지도의 아무 곳이나 클릭하면 그 자리에 불이 나고**, 사용자는 그 지점을 피해
다시 계산된 경로를 음성으로 안내받는다. 통로를 고르는 게 아니라 **좌표를 찍는다** —
실제 화재는 우리가 그려 둔 통로 선 위가 아니라 복도 한가운데나 방 안에서 나기 때문이다.

어떤 통로가 막히는지는 **점과 선분 사이의 최단거리**로 판정한다. 통로 양 끝점까지의
거리만 재면 복도 한가운데 난 불을 놓친다.

| 화재 지점과의 거리 | 판정 |
|---|---|
| 반경 이내 | 통행 불가 — 경로에서 제외 |
| 반경 × 1.7 이내 | 화재 인접(열기) — 통행은 되지만 가중치 ×4로 크게 우회 |
| 그 밖 | 영향 없음 |

관제의 **화재 발생** 도구에서 반경(2~25m)을 정하고 지도를 클릭한다.
화재 목록의 **＋ 확산**으로 반경을 넓히면 불이 번지는 상황을 재현할 수 있고,
결국 교차점까지 삼키면 사용자는 **안전상태로 전환해 구조요청**을 보낸다.

실제 시연 결과 (가천관 3층, 312호 강의실 앞 출발):

```
평상시          312호 → 중앙 로비 → 북측 복도 → 서편 비상계단 (32.7m)
                "정면으로 15걸음 이동하세요. 오른쪽 벽을 따라가세요."

(450, 280)에 화재 반경 3m
                자동 판정: 북측 복도와 서편 비상계단 사이 통로 차단
                [긴진동 3회] "위험. 앞쪽에 화재가 발생했습니다. 경로를 다시 계산합니다."
                재탐색 0.13ms → 312호 → 중앙 로비 → 북측 복도 → 동편 비상계단
                [짧은진동 2회] "오른쪽으로 도세요." "정면으로 20걸음 이동하세요."

반경 20m로 확산   경로 없음 → "제자리에서 구조요청을 전송합니다."
```

재탐색 사유는 **원인별로 다르게** 읽어준다 — "통로 상태가 변경되었습니다"보다
"앞쪽에 화재가 발생했습니다"가 몸이 먼저 반응하는 문장이기 때문이다.

## 온도 센서 회피

온도 센서 판독값이 임계값을 넘으면 **그 구간을 자동으로 빼고** 경로를 다시 잡는다.

| 온도 | 판정 | 경로탐색 처리 |
|---|---|---|
| 60°C 이상 | 과열 — 통행 불가 | 그래프에서 제외 |
| 45°C 이상 | 온도 상승 | 통행은 가능하되 가중치 ×4로 강하게 회피 |
| 그 미만 | 정상 | 영향 없음 |
| 60초 이상 갱신 없음 | 판독 끊김 | **신뢰하지 않음** — 오래된 값으로 안내하지 않는다 |

센서는 **통로(edgeId)** 또는 **지점(nodeId)** 에 붙는다.
교차점이 뜨거우면 어느 방향으로도 지날 수 없으므로, 지점 센서가 과열되면
그 지점에 연결된 **모든 통로**를 막는다.

```bash
# 실제 센서 게이트웨이·BMS가 호출하는 것과 동일한 엔드포인트
curl -X POST http://localhost:5173/api/sensors/temperature \
  -H 'Content-Type: application/json' \
  -d '{"sensorId":"TMP-C4","edgeId":"C4","celsius":71}'
```

관제 대시보드의 **온도** 도구는 이 API를 그대로 호출한다 —
시뮬레이션과 실제 연동의 경로를 분리하지 않아야 실증에서 그대로 쓸 수 있기 때문이다.
지도에는 판독값이 배지로 표시되고, 판독이 끊긴 센서는 흐리게 표시된다.

관제가 지정한 위험과 센서 판정이 겹치면 **더 심각한 쪽**을 채택한다.
센서가 정상이라는 이유로 관제가 막아둔 통로를 열어주면 안 되기 때문이다.

## 보호자 위치 공유

사용자가 **대피 전에 미리** 보호자를 등록해 두면(이름·연락처), 6자리 공유 코드와 링크가 발급된다.
보호자가 그 링크를 열어두면 화재로 대피가 시작되는 순간부터 다음이 실시간으로 표시된다.

- 상태 배너 (대기 중 / 대피 중 / 구조 요청 / 대피 완료) + **브라우저 알림·진동**
- 지도 위 대상자 위치, 안내 중인 경로, 위험 통로
- **지금 대상자가 듣고 있는 음성 안내 그대로** ("정면으로 9걸음 이동하세요…")
- 위치 확신도, 목표 출구, 남은 걸음 수, 상황 기록

알림은 상태가 **바뀌는 순간에만** 울린다 — 걸음마다 울리면 보호자가 알림을 꺼버리기 때문이다.

구조요청이 발생하면 관제 대시보드의 SOS 카드에 **보호자 이름·연락처가 함께** 표시되어
구조대가 바로 연락할 수 있다.

### 개인정보 경계

보호자 스트림은 `?code=`로 **스코프가 제한**된다. 코드에 연결된 대상자의 위치·구조요청·알림만
내려가고, 다른 대피자의 위치와 운영 지표(metrics)는 전달되지 않는다.
MVP의 코드 기반 링크는 시연용이며, 실서비스에서는 보호자 본인확인·코드 만료·공유 철회가 필요하다.

## 사용자 앱 — 실제 화재 상황 기준

설계 기준은 하나다. **화면을 보지 않고, 한 손으로, 흔들리는 몸으로 쓸 수 있는가.**

### 화면 전체가 조작면

대피 중에는 작은 버튼을 찾을 수 없다. 그래서 안내 영역 전체가 하나의 버튼이다.

| 동작 | 결과 |
|---|---|
| 한 번 두드리기 | 지금 안내 다시 듣기 |
| 두 번 두드리기 | 여기가 어디인가요 (저장된 장소 설명) |
| 위로 쓸기 | 방향 찾기 켜기/끄기 |
| 볼륨 올리기 버튼 3회 누르기 | 첫 입력 후 4초 안에 세 번 누르면 발신 — 입력마다 남은 횟수를 음성·진동으로 확인 |

구조요청은 첫 번째와 두 번째 볼륨 올리기 입력에서 남은 횟수를 음성·진동으로 알려준다. 4초 안에 세 번째 입력이 없으면 자동으로 취소된다. 모바일 브라우저의 시스템 볼륨 키 전달은 기기마다 달라 실사용 기능으로 신뢰할 수 없으므로, Android 네이티브 셸은 볼륨 키 입력 시 `window.fireGuideVolumeUp()`을 호출해야 한다. 브라우저 시연에서는 접힌 시연 패널의 `볼륨 올리기 입력` 버튼으로 같은 동작을 검증한다.

### 화면 구성

```
대기            대피 중                 안전 대기            완료
┌──────────┐   ┌──────────┐          ┌──────────┐      ┌──────────┐
│ 내 위치   │   │ → 서편계단 15걸음 │  │    SOS    │      │    완료   │
│          │   │                  │  │ 그 자리에서│      │ 대피 완료 │
│ ┌──────┐ │   │ 정면으로         │  │  기다리세요│      │          │
│ │대피  │ │   │ 15걸음 이동      │  │          │      │          │
│ │대피시작│ │   │                  │  │ 내 위치:  │      │          │
│ └──────┘ │   │ [방향 미터]       │  │ 중앙 로비 │      │          │
│ QR / 목록 │   │ [작은 지도]       │  │          │      │          │
│          │   │ [볼륨 올리기 3회] │  │          │      │          │
└──────────┘   └──────────┘          └──────────┘      └──────────┘
```

- **대피 시작 버튼이 화면의 절반**이다. 눈을 감고도 찾을 수 있어야 한다.
- 마지막으로 확인한 위치를 기억해 둔다 — 불이 났을 때 위치부터 고르게 하지 않는다.
- 홈 화면에 설치하면 **"바로 대피 시작"** 바로가기가 생긴다 (`?start=1`).

### 응급 상황에서 버티는 장치

| 상황 | 대응 |
|---|---|
| 화면이 꺼짐 | **Wake Lock**으로 대피 중 화면을 켜 둔다. 앱 복귀 시 다시 잡는다 |
| 앱이 죽었다 켜짐 | 마지막 지점에서 **자동으로 이어서 안내** (30분 이내·같은 도면일 때만) |
| 실수로 페이지 닫기 | 대피 중이면 확인을 묻는다 |
| 배터리 부족 | 20% 이하이면 상태줄에 경고 |
| 서버 끊김 | 캐시된 도면으로 오프라인 안내 계속 (상태줄에 표시) |
| 도착·구조요청 | 방향 신호를 **자동으로 끈다** — 움직이면 안 되는 상황이므로 |

### 접근성

- 안내 문구는 `aria-live="assertive"` — 스크린리더가 즉시 읽는다
- 색만으로 상태를 전하지 않는다 (아이콘·문구 병기)
- 노치·홈바 안전영역(`env(safe-area-inset-*)`) 반영, 가로 모드에서는 지도를 접고 글자를 지킨다
- `prefers-reduced-motion` 존중

## 방향 찾기 — 금속탐지기처럼 훑어서 각도 맞추기

"오른쪽으로 30도 도세요"는 듣고 몸으로 옮기는 데 시간이 걸린다.
대신 **폰을 쥔 손을 좌우로 훑으면**, 맞는 방향에서 진동이 끊기지 않고 이어진다.
사용자는 각도를 계산할 필요 없이 **"진동이 안 끊기는 쪽"** 만 찾으면 된다.

| 목표 방향과의 오차 | 신호 | 느낌 |
|---|---|---|
| 0~8° | **잠김** | 우우우웅——  (끊김 없는 연속 진동) |
| 8~20° | 근접 | 우웅-우웅-  (짧게 끊김) |
| 20~40° | 멀다 | 툭... 툭... |
| 40~70° | 가장자리 | 툭...... 툭...... |
| 70°~ | 없음 | 무음 |

행동 유도는 한 문장이다 — **"진동이 끊기지 않는 방향으로 그대로 걸으세요."**

- 목표 방위는 **지금 걷고 있는 통로의 방위**다. 회전 지점을 지나면 자동으로 다음 통로를 향한다.
- 나침반이 없거나 방위를 모르면 **아무 신호도 주지 않는다.** 모르는 채로 진동을 주면
  잘못된 쪽으로 걷게 되기 때문이다.
- **도착했거나 안전상태(제자리 대기)로 바뀌면 자동으로 꺼진다.** 움직이면 안 되는 상황에서
  방향 신호를 계속 주면 안 된다.
- iOS Safari는 Vibration API를 지원하지 않으므로 **같은 규칙으로 소리도 낸다**
  (맞을수록 높고 끊김 없는 음). 진동·소리 중 하나만 있어도 방향을 찾을 수 있다.

데스크톱에는 나침반이 없어서, 시연 콘솔에는 **다이얼**을 두었다. 마우스로 돌리거나
방향키(Shift로 15°씩)로 돌리면 소리로 체험할 수 있다. 신호 규칙은 실제 기기와 완전히 같다.

## 음성·진동 6개 명령

| 명령 | 진동 | 음성 예시 |
|---|---|---|
| 직진 | 짧게 1회 | "정면으로 9걸음 이동하세요. 오른쪽 벽을 따라가세요." |
| 우회전 | 짧게 2회 | "오른쪽으로 도세요. 그다음 12걸음 직진입니다." |
| 좌회전 | 짧게 3회 | "왼쪽으로 도세요. …" |
| 멈춤 | 길게 1회 | "멈추세요. 왼쪽으로 30도 돌려 통로를 찾으세요." |
| 위험 | 길게 3회 | "위험. 전방 통로 상태가 변경되었습니다." |
| 구조요청 | 매우 길게 2회 | "제자리에서 구조요청을 전송합니다. 이동하지 말고 대기하세요." |

## 오픈소스 출처 (MIT)

- **[Anyplace](https://github.com/dmsl/anyplace)** (Univ. of Cyprus DMSL) —
  POI/Connection 그래프 모델과 `server/app/utils/Dijkstra.scala` 경로탐색을 `shared/pathfinding.js`로 포팅.
- **[Visual_Slam](https://github.com/ravencore06/Visual_Slam)** (Prototype/Academic) —
  PWA 구조, devicemotion 걸음감지·방위추적(`odometry.js`), TTS·진동 접근성 모듈 참고.

오픈소스로 해결되지 않는 부분(공식 안전규칙, 위치 인프라, 당사자 실증, 책임·인증)은
MVP에서 **모의 데이터·시뮬레이션**으로 대체했다. 다만 두 가지는 실제 연동 경로를 열어 두었다:

- **도면** — `POST /api/plans`로 주입. BIM/CAD에서 내보낸 그래프를 같은 형식으로 넣으면 된다.
- **센서** — `POST /api/sensors/temperature`(온도), `POST /api/sensors/fire-panel`(화재수신기).
  관제 시뮬레이션도 같은 API를 쓰므로 실증에서 배선만 바꾸면 된다.

## 안전 고지

이 소프트웨어는 **모의대피 실험·UX 검증용 프로토타입**이며 재난안전 인증 제품이 아니다.
실제 화재 대응 용도로 사용해서는 안 된다.
